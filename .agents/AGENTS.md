# Workspace Rules

## "ok push" Automation

Whenever the user writes **"ok push"** (case-insensitive, with or without punctuation), you MUST immediately and automatically perform the following git commands in the project directory without asking for confirmation:

1. `git add .` — stage all changes
2. `git commit -m "<auto-generated message describing recent changes>"` — write a short, meaningful commit message based on what files were changed
3. `git push` — push to the remote GitHub repository

### Rules:
- Do NOT ask the user for a commit message — generate one yourself based on context (e.g., what files changed).
- Do NOT ask for confirmation before running these commands.
- After pushing, report back: the commit message used, the files committed, and the push result.
- If git is not initialized or there is no remote, inform the user and guide them to set it up.
- Always run commands from the root of the active project/workspace directory.
